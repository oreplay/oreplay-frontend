# Android app (Trusted Web Activity)

> [!WARNING]
> These instructions were autogenerated with AI and may contain mistakes.

This directory is a [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) project that wraps
the PWA into an installable Android app. Only three files are committed:

- `twa-manifest.template.json` — every Bubblewrap setting that does **not** depend on the deployment.
- `generate-twa-manifest.mjs` — merges the template with the repo's `.env` into `twa-manifest.json`.
- this README.

Everything else (`twa-manifest.json`, the Gradle project, keystore, APK/AAB, logs) is generated
locally and gitignored.

## Configuration (`.env`)

| Variable                       | Used for                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| `VITE_WEBSITE_DOMAIN`          | Deployment URL: TWA host, icon and manifest URLs, CORS origin, CI smoke test.              |
| `VITE_VERSION_NUMBER`          | `appVersionName`; `appVersionCode` is `major*1000000 + minor*1000 + patch`.                |
| `TWA_PACKAGE_ID`               | Android application ID and `assetlinks.json` package name.                                 |
| `TWA_SHA256_CERT_FINGERPRINTS` | Comma-separated signing certificate fingerprints for `assetlinks.json`.                    |
| `TWA_KEYSTORE_PATH` (optional) | Keystore path relative to this dir (default `android.keystore`).                           |
| `TWA_KEY_ALIAS` (optional)     | Key alias (default `android`).                                                             |
| `TWA_ASSETS_ORIGIN` (optional) | Origin Bubblewrap downloads the icons and web manifest from (default: the deployment URL). |

Machine-specific values (keystore path, a local test URL) belong in `.env.local` /
`.env.production.local`, which are gitignored and override `.env`.

## Prerequisites

- **JDK 17 exactly.** Bubblewrap 1.25.0 reads the JDK's `release` file and requires a literal
  `JAVA_VERSION="17.0` entry — it rejects both newer and older JDKs, including Android Studio's
  bundled JetBrains Runtime (which is JDK 21+ on recent Android Studio versions). Install one, e.g.
  [Eclipse Temurin 17](https://adoptium.net/temurin/releases/?version=17).
- **Android SDK**, with `cmdline-tools` installed (via Android Studio's SDK Manager, or
  `sdkmanager --install "cmdline-tools;latest"`).
- `npm install -g @bubblewrap/cli`

### Known Bubblewrap/SDK quirks on macOS

Bubblewrap's path validation has a few rough edges with current Android Studio / SDK layouts that
you may need to work around locally (these are environment fixes, not project files):

- `bubblewrap doctor` computes the Java home as `<jdkPath>/Contents/Home/` on macOS — so
  `jdkPath` must point at the **`.jdk` bundle root** (e.g.
  `/Library/Java/JavaVirtualMachines/temurin-17.jdk`), not at `.../Contents/Home` itself.
- Some newer Temurin 17 builds' `release` file omits the `JAVA_VERSION=` key Bubblewrap greps for
  (it only has `JAVA_RUNTIME_VERSION`). If `bubblewrap doctor` reports "JDK version not supported"
  despite having a real JDK 17 installed, inspect
  `<jdk>/Contents/Home/release` for a `JAVA_VERSION="17.0...` line.
- `bubblewrap doctor` requires the SDK root to contain a `tools/` or `bin/` folder, which modern
  SDK installs (cmdline-tools only) don't have by default. An empty `tools/` folder is enough to
  pass the check.
- `bubblewrap build` looks for `sdkmanager` at `<sdk>/bin/sdkmanager` (the legacy location); modern
  SDKs only ship it under `cmdline-tools/latest/bin/`. Symlink `<sdk>/bin` to
  `<sdk>/cmdline-tools/latest/bin` to fix this.

Configure the resolved paths once with:

```
bubblewrap updateConfig --jdkPath <path-to-jdk-bundle> --androidSdkPath <path-to-android-sdk>
bubblewrap doctor   # should report both paths valid
```

## Building locally

1. Deploy the PWA (or serve it over HTTPS at `VITE_WEBSITE_DOMAIN`) so Bubblewrap can read its
   manifest.
2. From the repo root, generate `twa-manifest.json` and (re)generate the Gradle project:
   ```
   npm run twa:update
   ```
   (`npm run twa:manifest` only writes `twa-manifest.json`; pass a Vite mode to read
   `.env.<mode>` files, e.g. `npm run twa:manifest -- staging`.)
3. From this directory, run:
   ```
   bubblewrap build
   ```
   It prompts for the keystore and key passwords (never commit them), downloads Android build
   tools on first run, and produces `app-release-signed.apk` and `app-release-bundle.aab`.

`bubblewrap init` is not needed: `bubblewrap update` regenerates the whole Gradle project from
`twa-manifest.json`. To change a non-deployment setting (colors, orientation, …) edit
`twa-manifest.template.json` and re-run `npm run twa:update`.

## CI build

On every version tag, after the web app is deployed, the `android-apk` job of
`.github/workflows/ci.yml` builds the APK and uploads it as the workflow artifact
`oreplay-<version>-throwaway-signed-apk`. It can also be started by hand from the Actions tab
(`workflow_dispatch`), which skips the deployment.

- The job serves the freshly built `dist/` on `localhost` and sets `TWA_ASSETS_ORIGIN` to it, so the
  icons come from that build rather than from the live site.
- The APK is signed with a **throwaway key generated in the job**. It is installable for testing,
  but each run uses a different key: uninstall the previous build before installing a new one, and
  the app opens with a browser bar because the key is not listed in `assetlinks.json`. It must not
  be published.

## Signing key & Digital Asset Links

A Trusted Web Activity only opens without a browser bar if
`<VITE_WEBSITE_DOMAIN>/.well-known/assetlinks.json` lists the app's package and signing
certificate. `npm run build` generates that file from `TWA_PACKAGE_ID` and
`TWA_SHA256_CERT_FINGERPRINTS` (it is skipped, with a warning, while the fingerprint list is empty).

1. Create the production keystore **outside the repo** and keep its passwords in a password
   manager / CI secrets.
2. Get its fingerprint: `keytool -list -v -keystore <path> -alias <alias>` (the `SHA256:` line).
   If you use Play App Signing, also add the **app signing key** fingerprint from Play Console →
   Setup → App integrity.
3. Put the fingerprints in `TWA_SHA256_CERT_FINGERPRINTS` (comma-separated), deploy the web app,
   and check `https://<domain>/.well-known/assetlinks.json`.
